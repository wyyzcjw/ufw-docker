# UFW-Docker Rule Lifecycle

`ufw-docker-rulectl` is the fork-specific lifecycle companion for managed UFW rules. It exists to keep the upstream `ufw-docker` core close to `chaifeng/ufw-docker` while still giving `allow-ip` rules the same operational lifecycle as ordinary rules.

## Why it exists

The fork adds comments such as:

```text
# allow nginx 443/tcp frontend from:192.0.2.0/24
# allow nginx/v6 443/tcp frontend from:2001:db8::/64
```

The upstream list/delete/reload parser was designed for comments without the trailing `from:` token. Rather than duplicating the entire upstream core, the lifecycle layer parses only rules carrying the managed `# allow ...` comment.

From `1.5.1`, source-restricted rules also use the lifecycle layer for address-family-safe creation and reload. This avoids a dual-stack edge case in the legacy core `allow-ip` path, which walks both IPv4 and IPv6 container target addresses even when the source belongs to only one family.

## Commands

List every managed rule:

```bash
sudo ufw-docker-rulectl list
```

Machine-readable output:

```bash
sudo ufw-docker-rulectl list --format tsv
```

Filter by container, container port, Docker network or source:

```bash
sudo ufw-docker-rulectl list \
  --container nginx \
  --port 443/tcp \
  --network frontend \
  --source 192.0.2.0/24
```

Delete matching managed rules:

```bash
sudo ufw-docker-rulectl delete --container nginx --source 192.0.2.0/24
```

Preview deletion without changing UFW:

```bash
sudo ufw-docker-rulectl delete --container nginx --dry-run
```

Reload normal and source-restricted rules after container IP changes:

```bash
sudo ufw-docker-rulectl reload
```

Preview the commands generated by reload:

```bash
ufw-docker-rulectl reload --dry-run
```

## Dual-stack source rules

For source-restricted rules, the source address family determines which Docker target address is used:

```text
IPv4 source -> IPv4 container target only
IPv6 source -> IPv6 container target only
```

A dual-stack Docker network is therefore valid for both source families. The helper skips the opposite target family instead of aborting the operation or attempting an invalid IPv4-to-IPv6 / IPv6-to-IPv4 UFW rule.

The interactive menu uses the same shared helper, so adding a new source rule and later reloading it follow the same behavior.

## Safety properties

- Only UFW entries carrying the `# allow ...` managed comment are considered.
- Deletion uses UFW rule numbers in descending order so numbering changes do not corrupt the remaining deletion set.
- IPv4 and IPv6 copies of the same logical rule are deduplicated before reload.
- Ordinary rules are recreated through `ufw-docker allow`.
- Source-restricted rules are recreated through the shared family-aware UFW helper, which only selects Docker targets matching the source address family.
- Reload failures are reported and old rules are not automatically deleted.
- No `eval` is used; commands are assembled as Bash arrays.
- `--format tsv` provides a stable machine-readable view for the interactive menu and future tooling.

## Installation

The interactive menu installer installs the lifecycle helper together with the menu:

```bash
sudo ./install-menu.sh
```

Installed paths:

```text
/usr/local/bin/ufw-docker-rulectl
/usr/local/lib/ufw-docker/ufw-docker-rules.sh
```

The upstream-compatible `ufw-docker` script remains responsible for ordinary container rules. Source-restricted rules created through the menu/lifecycle tools use the shared family-aware helper described above.
