# UFW-Docker Rule Lifecycle

`ufw-docker-rulectl` is the fork-specific lifecycle companion for managed UFW rules. It exists to keep the upstream `ufw-docker` core close to `chaifeng/ufw-docker` while still giving `allow-ip` rules the same operational lifecycle as ordinary rules.

## Why it exists

The fork adds comments such as:

```text
# allow nginx 443/tcp frontend from:192.0.2.0/24
# allow nginx/v6 443/tcp frontend from:2001:db8::/64
```

The upstream list/delete/reload parser was designed for comments without the trailing `from:` token. Rather than duplicating the entire upstream core, the lifecycle layer parses only rules carrying the managed `# allow ...` comment and delegates actual rule creation back to the existing core command.

## Commands

List every managed rule:

```bash
sudo ufw-docker-rulectl list
```

Machine-readable output:

```bash
sudo ufw-docker-rulectl list --format tsv
```

Filter by container, container port, Docker network or source:

```bash
sudo ufw-docker-rulectl list \
  --container nginx \
  --port 443/tcp \
  --network frontend \
  --source 192.0.2.0/24
```

Delete matching managed rules:

```bash
sudo ufw-docker-rulectl delete --container nginx --source 192.0.2.0/24
```

Preview deletion without changing UFW:

```bash
sudo ufw-docker-rulectl delete --container nginx --dry-run
```

Reload normal and source-restricted rules after container IP changes:

```bash
sudo ufw-docker-rulectl reload
```

Preview the commands generated by reload:

```bash
ufw-docker-rulectl reload --dry-run
```

## Safety properties

- Only UFW entries carrying the `# allow ...` managed comment are considered.
- Deletion uses UFW rule numbers in descending order so numbering changes do not corrupt the remaining deletion set.
- IPv4 and IPv6 copies of the same logical rule are deduplicated before reload.
- Rule recreation is delegated to `ufw-docker allow` or `ufw-docker allow-ip`; the lifecycle helper does not duplicate iptables/UFW creation logic.
- Reload failures are reported and old rules are not automatically deleted.
- No `eval` is used; commands are assembled as Bash arrays.
- `--format tsv` provides a stable machine-readable view for the interactive menu and future tooling.

## Installation

The interactive menu installer installs the lifecycle helper together with the menu:

```bash
sudo ./install-menu.sh
```

Installed paths:

```text
/usr/local/bin/ufw-docker-rulectl
/usr/local/lib/ufw-docker/ufw-docker-rules.sh
```

The upstream-compatible `ufw-docker` script remains the command responsible for adding firewall rules.
